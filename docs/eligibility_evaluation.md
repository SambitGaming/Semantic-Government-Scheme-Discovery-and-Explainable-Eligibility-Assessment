# Eligibility Evaluation

## 1. Objective

The eligibility assessment module was evaluated using
predefined gold applicant profiles.

For each profile, the expected eligibility outcome was
compared with the result generated by the deterministic
eligibility engine.

The purpose of the evaluation is to measure the correctness
and reliability of the eligibility assessment module.

---

## 2. Evaluation Dataset

The evaluation dataset consists of gold applicant profiles
covering different eligibility situations, including:

- Eligible applicants
- Ineligible applicants
- Boundary conditions
- Income mismatches
- State mismatches
- Category mismatches
- Education mismatches
- Other scheme-specific eligibility conditions
- Profiles with multiple eligibility failures

The expected results were defined before evaluation and were
not modified to improve the measured performance.

---

## 3. Evaluation Method

Eligibility results were converted into binary classes:

- Eligible = Positive
- Not Eligible = Negative

The expected result was treated as the ground truth and the
eligibility engine output was treated as the prediction.

The following metrics were calculated:

- Accuracy
- Precision
- Recall
- F1-score
- True Positives
- True Negatives
- False Positives
- False Negatives

---

## 4. Accuracy

Accuracy measures the proportion of applicant profiles for
which the eligibility engine produced the correct final result.

Formula:

Accuracy = (TP + TN) / (TP + TN + FP + FN)

The measured accuracy is recorded in:

`results/eligibility/eligibility_metrics.csv`

---

## 5. Precision

Precision measures the proportion of applicants classified as
eligible who were actually expected to be eligible.

Formula:

Precision = TP / (TP + FP)

Precision is particularly relevant because a false positive
can incorrectly indicate that an applicant satisfies the
eligibility requirements.

---

## 6. Recall

Recall measures the proportion of applicants who were actually
eligible and were correctly identified by the system.

Formula:

Recall = TP / (TP + FN)

Recall is useful for identifying eligible applicants that the
system incorrectly rejects.

---

## 7. F1-score

F1-score combines precision and recall into a single metric.

Formula:

F1 = 2 × Precision × Recall / (Precision + Recall)

---

## 8. Confusion Matrix

The evaluation distinguishes four outcomes:

### True Positive

The applicant was expected to be eligible and the system
classified the applicant as eligible.

### True Negative

The applicant was expected to be not eligible and the system
classified the applicant as not eligible.

### False Positive

The applicant was expected to be not eligible but the system
classified the applicant as eligible.

### False Negative

The applicant was expected to be eligible but the system
classified the applicant as not eligible.

---

## 9. Error Analysis

Incorrect predictions are stored in:

`results/eligibility/eligibility_errors.csv`

False positives and false negatives are investigated by
examining the individual eligibility rules associated with
the affected applicant profiles.

Potential causes include:

- Incorrect rule encoding
- Incorrect boundary conditions
- Incorrect applicant data
- Missing applicant information
- Ambiguous scheme requirements
- Incorrect interpretation of an official eligibility rule

---

## 10. Rule-Level Evaluation

In addition to evaluating the final eligibility decision,
individual rule evaluations are summarized.

The rule-level analysis identifies the number of evaluated
rules, passed rules, failed rules, and the pass rate for each
rule field.

The resulting summary is stored in:

`results/eligibility/rule_level_summary.csv`

Rule failures are not automatically treated as system errors.
A rule may correctly fail when an applicant does not satisfy
the corresponding eligibility requirement.

---

## 11. Explainability and Traceability

The eligibility system records the individual rules used to
reach a decision.

The explanation data can include:

- Profile ID
- Scheme ID
- Rule ID
- Applicant value
- Required value
- Operator
- Rule result
- Explanation
- Rule version
- Official source URL

This provides traceability from the final eligibility decision
to the individual eligibility rules.

---

## 12. Reproducibility

The evaluation can be reproduced using:

- The same gold profiles
- The same eligibility rules
- The same rule versions
- The same eligibility engine
- The same evaluation scripts

The generated evaluation files provide a record of the
measured results.

---

## 13. Limitations

The evaluation depends on the quality and coverage of the gold
profiles and the correctness of the manually encoded
eligibility rules.

The evaluation dataset may not represent every possible
real-world applicant.

Some government eligibility requirements may also require
manual verification or information that cannot be represented
completely through deterministic rules.

Therefore, evaluation results should be interpreted within the
scope of the tested gold profiles and implemented rules.
